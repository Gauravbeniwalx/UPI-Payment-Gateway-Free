# HDFC Bank UPI / UTR Verification System

This system receives HDFC Bank transaction notifications through Gmail, automatically extracts UTR/payment information, stores the last 10 days of transactions locally, continuously monitors new notifications, and provides a simple UTR verification API.

It also provides a professional UPI QR page with **NO FIXED AMOUNT**.

---

# 1. SYSTEM FLOW

Customer
   ↓
Scan UPI QR
   ↓
Enter any amount in UPI app
   ↓
Payment to your UPI ID
   ↓
HDFC Bank
   ↓
HDFC transaction notification
   ↓
Gmail Inbox
   ↓
Python IMAP Collector
   ↓
Extract UTR / Amount / Sender / Date
   ↓
SQLite Database
   ↓
/verify-utr API


IMPORTANT:
The QR does NOT contain a fixed amount.

The customer can pay ₹10, ₹100, ₹500, ₹1000, etc.

# 9. WHAT EACH .env VARIABLE MEANS

GMAIL_USER

The Gmail account receiving HDFC transaction emails.

Example:

GMAIL_USER=payments.demo@gmail.com


GMAIL_APP_PASSWORD

The 16-character Google App Password.

Example:

GMAIL_APP_PASSWORD=abcdefghijklmnop

NOT your normal Gmail password.


UPI_ID

The UPI ID where you want to receive payments.

Example:

UPI_ID=demobusiness@hdfcbank

Use your REAL UPI ID.


PAYEE_NAME

Name shown in the UPI QR/payment information.

Example:

PAYEE_NAME=Demo Business


BUSINESS_EMAIL

Email displayed on the professional QR page.

Example:

BUSINESS_EMAIL=payments@yourbusiness.com


DB_PATH

Local SQLite database location.

Example:

DB_PATH=./hdfc_payments.db


SEARCH_DAYS

Number of previous days scanned when the system starts.

Keep:

SEARCH_DAYS=10

This means the system scans the previous 10 days when starting/restarting.


POLL_INTERVAL

How frequently the system checks Gmail for new messages.

Example:

POLL_INTERVAL=3

This means approximately every 3 seconds.


HDFC_EMAIL_FROM

The exact sender address of your HDFC transaction notification.

Example:

HDFC_EMAIL_FROM=alerts@hdfcbank.net

Use the actual address from your own HDFC email.


CREDIT_ONLY

Keep:

CREDIT_ONLY=true

This makes the system focus on incoming/credited transactions rather than outgoing/debit notifications.


PORT

Server port.

Keep:

PORT=8000

# 12. WHAT HAPPENS WHEN SERVER STARTS

On the first startup/restart, the system automatically scans the previous 10 days.

Flow:

Last 10 days of Gmail
        ↓
Find HDFC emails
        ↓
Identify transaction notifications
        ↓
Identify credit/incoming transactions
        ↓
Extract UTR
        ↓
Extract amount
        ↓
Extract sender if available
        ↓
Extract note/reference if available
        ↓
Save into SQLite


The database:

hdfc_payments.db

is created automatically.


---

# 13. HISTORY RETENTION

SEARCH_DAYS=10 means:

"Scan the previous 10 days when the collector starts."

It does NOT mean that old database records are automatically deleted after 10 days.

The system does not automatically delete transaction records.

Example:

Day 1  → saved
Day 2  → saved
Day 10 → saved
Day 20 → saved
Day 30 → saved
Day 100 → saved

The records remain in SQLite unless you manually remove the database.


---

# 14. LIVE TRANSACTION MONITORING

After the initial 10-day scan, the system continuously checks Gmail for new messages.

With:

POLL_INTERVAL=3

the collector checks approximately every 3 seconds.

Flow:

New HDFC notification
        ↓
Gmail
        ↓
Collector detects email
        ↓
Extract UTR
        ↓
Save transaction
        ↓
Available through API

# 18. UTR VERIFICATION API

Main API:

GET /verify-utr?utr=YOUR_UTR


Example:

https://yourdomain.com/verify-utr?utr=123456789012


If the UTR exists:

{
    "found": true,
    "verified": true,
    "utr": "123456789012",
    "amount": 500.0,
    "sender_name": "CUSTOMER NAME",
    "note": "PAYMENT",
    "received_at": "2026-09-24T04:12:31+00:00",
    "bank": "HDFC Bank",
    "source": "HDFC_BANK_EMAIL"
}


If the UTR does not exist:

{
    "found": false,
    "verified": false,
    "utr": "123456789012",
    "bank": "HDFC Bank",
    "source": "HDFC_BANK_EMAIL",
    "message": "UTR not found in cached HDFC transaction emails"
}


---

# 19. POST UTR API

You can also use:

POST /verify-utr

JSON body:

{
    "utr": "123456789012"
}


Example using JavaScript:

fetch("https://yourdomain.com/verify-utr", {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify({
        utr: "123456789012"
    })
})
.then(response => response.json())
.then(data => {
    console.log(data);
});

# 20. HOW YOUR MAIN WEBSITE SHOULD CHECK PAYMENT

Your application can call:

GET /verify-utr?utr=USER_ENTERED_UTR


If response contains:

"verified": true

then the UTR was found in the locally collected HDFC transaction notifications.

If:

"verified": false

then the UTR was not found.


IMPORTANT:

Do not grant payment-based access merely because the user entered an amount.

Use the UTR verification response.

Also prevent the same UTR from being processed multiple times in your own business/order database.

# 25. IF UTR IS NOT FOUND

Check these things in order:

1. Did HDFC send the transaction email?
2. Did that email arrive in the configured Gmail account?
3. Is GMAIL_USER correct?
4. Is GMAIL_APP_PASSWORD correct?
5. Is HDFC_EMAIL_FROM correct?
6. Is the transaction actually a credit/incoming transaction?
7. Check /collector/status for last_error.
8. Check the server console logs.
9. Check the exact UTR/reference shown in the HDFC email.

# 30. IMPORTANT VERIFICATION LIMITATION

This system is an email-based UTR verification system.

It works like:

HDFC Bank
→ Transaction notification
→ Gmail
→ IMAP
→ Python collector
→ SQLite
→ UTR API


It is NOT a direct HDFC Bank/NPCI transaction-status API.

Therefore:

"verified": true

means that the supplied UTR was successfully matched against a collected HDFC transaction notification stored by this system.

Before enabling automatic order/service fulfilment, perform real end-to-end testing with your actual HDFC notification format.
